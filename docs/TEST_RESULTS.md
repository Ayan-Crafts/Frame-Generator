# Test results — TrackNetV1 Dataset Prepper 2.1.0

All results below were produced on 2026-11-18 by actually running the
commands listed. Nothing is extrapolated. Where something could not be
tested, it says so.

## 2. Automated test suite

89 tests (`tests/`), synthetic media generated by FFmpeg test sources.

| Run | Environment | Result |
|---|---|---|
| Developer venv | WIN | 89 passed, 0 skipped |
| Isolated build venv (`build_windows.ps1`) | WIN | **89 passed**, 0 skipped (196.6 s) |
| Linux build (`build_linux.sh`), no GPU flags | UBU | 82 passed, 5 skipped (GPU tests: NVDEC not available without the `video` capability — reported, not faked) |
| Linux build with GPU flags | UBU | **87 passed**, 0 skipped (59.5 s) — run before the 2 newest GUI tests were added |

Coverage by area:

* **Extraction correctness** — every output frame count equals FFprobe's
  decoded count (`-count_frames`) for H.264 MP4, MPEG-4 AVI (odd 321×181
  size), MJPEG MOV, H.264 MKV (no container frame count), VP9 WebM, and a
  Unicode file name; JPEG dimensions match the source; names
  `000001.jpg…` contiguous; `.complete` written.
* **Invalid input** — empty file, text file, broken header, audio-only,
  missing file, truncated file (frames kept, not marked complete).
* **GPU** (WIN and UBU) — NVDEC pipeline frame count equals CPU; AUTO falls
  back to CPU for H.264 4:4:4; forced GPU mode reports the failure.
* **Resume seam** — for 4 containers × 5 resume points × CPU and GPU, the
  resumed output is byte-identical to an uninterrupted extraction; plus a
  timed pause → truncated last frame → resume test.
* **Control** — stop-and-keep, cancel-and-delete, already-complete skip,
  concurrent exports.
* **Disk space** — refuses to start (< 0.5 GB), stops safely when the disk
  fills mid-export.
* **Dependency detection** — FFmpeg version parsing (release and git builds),
  minimum version gate, override/missing/bundled-vs-PATH resolution,
  `nvidia-smi` parsing (multi-GPU, `[N/A]`, new "CUDA UMD Version" header),
  report with no GPU, GPU present but FFmpeg without CUDA.
* **Dataset tools** — scanner (recursion, extensions, empty, missing),
  collision-free output names, resume inspection (gaps, truncated JPEG,
  markers), job persistence, converter (validation ratio, CSV layout,
  heatmap peaks, PNG option, missing images, usage errors, legacy script path).
* **CLI** — doctor JSON, extract (folder, failures, missing input), convert, version.
* **GUI** (offscreen Qt) — start-up and honest header, full batch export via
  the window, failed video does not stop the batch (summary shown), pause →
  resume through the window, cancel-&-delete while paused, input validation,
  annotation keyboard shortcuts, PLAY, click → save → CSV → reload, lazy
  tables, empty folder.

## 7. Not tested / limitations of this testing

* **Clean Windows machine**: all Windows tests ran on the development laptop
  (Python/FFmpeg/CUDA present). The installer was tested per-user in an
  isolated folder there; no pristine Windows VM was available. Use the
  checklist in `docs/INSTALLATION_WINDOWS.md` §6 on a clean machine.
* **All-users (admin) install** not executed (requires an elevation prompt).
* **Physical Ubuntu desktop**: Linux tests ran in Docker containers on WSL2
  (Xvfb for the GUI). Wayland sessions, application-menu launching in a real
  desktop environment and native NVIDIA Linux drivers were not exercised.
* **Other NVIDIA generations**: only an RTX 4050 (Ada) was available.
  Older GPUs differ in codec support; AUTO mode's per-video CPU fallback is
  the mitigation and is tested with streams no GPU can decode.
* **Long real-world footage**: benchmarks use synthetic noise-added test
  patterns, not the user's datasets (by request, user datasets were not used).
